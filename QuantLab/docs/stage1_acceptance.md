## iFinD 改动的交接决定

收尾前工作区已存在的 12 个文件改动，经检查保留在当前版本。方向为：

- access token 直连优先；被拒绝后提示重新配置，不尝试 refresh 回退。
- 旧 refresh token 模式仅为兼容保留；`auto` 在任一凭证存在时选择
  iFinD，两者均不存在时选择 AkShare。
- macOS 使用单独的 access-token 钥匙串条目，启动脚本向子进程注入
  access token 并清除旧 refresh 环境变量。
- 选择 iFinD 后的请求失败不静默改用 AkShare；日志和错误提示不输出凭证。

相关客户端、数据源工厂、钥匙串脚本和页面错误处理已纳入上述离线测试。
本次没有读取用户钥匙串，也没有验证真实账号授权或外部服务可用性。
两个跳过的测试分别是 AkShare 和 iFinD 的真实联网检查。
CSV 本地流程不依赖它们，阶段 2 可以基于已导入数据开始。

## 阶段 2 开发边界

继续复用当前行情服务、统一指标、基准与执行成本规则。因子目录保持
最小接口，第一阶段模块不依赖它。阶段 2 先定义多 ETF 数据对齐、可交易
状态和因子输出接口，再实现因子排名与组合调仓。

单 ETF 引擎仍保留单资产校验；新增多资产功能应扩展接口并保留全部
第一阶段测试。完整实验检索、旧代码环境自动恢复和因子有效性研究属于
后续阶段，本次记录功能仅提供可追溯基础。
