## 页面如何使用

1. 打开“因子研究”，选择已保存研究集合和一个内置因子。
2. 切换到“组合回测”。不必先在“因子观察”点击计算。
3. 设置选择数量 N、排名方向、调仓间隔和初始资金；高级设置中调整
   佣金、最低佣金、滑点、卖出税率和每手份额。页面费率单位是百分比，
   如 `0.03` 表示 `0.03%`，传入引擎时才除以 100。
4. 点击“运行组合回测”，查看指标、策略与基准净值对照、完整资金曲线、回撤及各类明细。

年化指标暂沿用每年 252 期、无风险年利率 0% 的固定假设。
指标未定义时显示 `—` 及原因，不填为零；最大回撤用负数表示跌幅。
没有成交也会显示完整现金路径，调仓和委托表解释未成交原因。

切换集合、因子、有效快照内容或回测参数会清除旧结果，须主动重新运行。
“因子观察”的查看日期、查看 ETF、排名方向及 Top N 预览只改变观察视图，
不会改变组合参数或截断回测日期轴。数据载入、模拟或指标分析失败后，
不保留上次成功结果或半次运行；原始错误中的私人路径不会直接显示。
未主动保存的本次结果仅在当前会话保留，不联网取数或自动存档；显式保存与下载见后文。

页面相关代码分别负责：

- `pages/7_因子研究.py`：共用集合/因子选择，分出观察与回测两个区域。
- `src/quantlab/ui/portfolio.py`：参数、运行按钮、旧结果失效和结果展示。
- `src/quantlab/ui/portfolio_display.py`：指标格式、图表、中文明细和安全错误提示。
- `tests/test_ui_portfolio.py`：用隔离的合成行情走真实导入、快照、回测和界面链路。
- `tests/test_ui_portfolio_display.py`：检查数值单位、完整日期轴、空值和错误信息。

界面调用 `run_factor_portfolio`、`analyze_portfolio_result` 和 `run_equal_weight_benchmark`，
没有复制或更改交易、收益和风险公式。更新程序后，旧进程可能仍持有旧代码；
若提示运行身份校验失败，应重启 QuantLab 后再运行，不能绕过版本校验。

## 全池等权买入持有基准

基准回答的是：在同一组 ETF、同一研究区间与交易假设下，单因子筛选和调仓
相对于“一次配置整个研究池并持有”有什么差别。它不是市场指数，也不证明策略有效。

- 全部 ETF 来自同一份已保存快照，不因因子有效与否挑选、剔除或替换 ETF。
- 设所选因子回看期为 L，日期轴从 0 开始：固定在位置 L+1 开盘一次建仓，
  之前持有现金。20 期动量/波动率对应第 22 个研究日期；20 期均线偏离/价格最大回撤的 L=19，
  对应第 21 个研究日期。都不以第一次策略实际成交日为锚点。
- 初始目标每只 `1 / ETF 数量`；沿用策略的初始资金、佣金、最低佣金、
  滑点、卖出税率和整手规则。实际份额由既有预算分配器决定，费用和余留现金
  会使权重偏离目标，之后价格变化也会改变权重。没有再平衡或期末强制卖出。
- L+1 不在区间内时显示完整现金曲线并注明“未到计划建仓日”。资金不足没有
  成交时也保留现金，不顺延到价格更低的日期重试。
- 计划建仓日任一目标缺开盘价、实际成交量为零，或正持仓缺收盘价时，基准失败；
  不填充价格、不取两条曲线的日期交集，也不缩短区间。策略若独立成功仍可展示，
  但必须明确“基准不可用”，不显示比较曲线和差值，更不保留旧基准。
- 两条净值起点均为 1，绩效均使用含热身和现金期的完整曲线。对比前严格核对
  快照、行情指纹、日期轴、初始资金与成本、指标参数和热身锚点。
- 累计收益差按 `(策略累计收益率 - 基准累计收益率) × 100` 显示为“个百分点”，
  不是收益率相除、净值之比或风险调整 alpha。未定义指标显示 `—`，不当作 0。

本步代码职责：

- `src/quantlab/portfolio/benchmark.py`：验证快照，生成一次全池目标，复用组合

- `src/quantlab/portfolio/analysis.py`：将原有指标计算提取为内部共用函数；

- `src/quantlab/ui/portfolio_display.py`：核对可比性，生成双色加虚实线的净值图、
  同口径指标表和百分点差；展示不截取、修改或补齐原曲线。

## 组合实验存档：保存、列出、重读核心

这一步让一次完成的研究可以脱离原行情目录保留下来。核心先提供 Python 入口，
随后接入下一节的界面；不自动保存、不重跑策略，也不改变第一阶段的回测档案。

### 三部分代码分别做什么

1. `src/quantlab/portfolio/archive_codec.py`：把日期、数值、空值和表格类型
   转成标准 JSON，再按固定结构恢复。核对数据网格、输入指纹、运行身份、
   指标日期、委托成交关系，以及现金和持仓账务；不执行存档中的公式文本。
2. `src/quantlab/portfolio/archive.py`：管理保存、列表与读取。保存前验证，
   用临时文件写完后才发布；读取只恢复历史值，坏文件单独报告。
3. `tests/test_portfolio_archive.py`：使用临时合成数据验证往返一致、源文件移走、
   空表和缺失值、基准失败、拒绝覆盖、损坏隔离、版本差异和中途写入失败。

### 每份档案保留什么

- 实验名称、保存时间、档案格式版本 `portfolio-archive-v1` 和整体内容指纹。
- 策略原始运行编号、运行时间、代码与依赖版本、因子说明、全部参数和警告。
- 独立行情及因子快照，以及调仓、目标、订单、成交、持仓、资产曲线六张结果表。
- 当时计算的每日收益、净值、回撤、五项指标，以及指标未定义的原因。
- 可选基准的独立身份、行情快照、六张表及绩效。基准没有因子快照，
  目标表的因子值保留为空，不能误当作数值为 0 的因子。

建议保存在 `data/portfolio_runs/`（已加入 Git 忽略规则）。每份为
`<策略原始 run_id>.json`：保存不生成新的运行身份，同一次运行不能覆盖或再次另名保存。
名称只是标签，不用于拼接路径。策略与基准的数据、区间、参数和热身锚点必须一致。
标准 JSON 用 `null` 表示允许的缺失值，禁止非标准的 `NaN` 和 `Infinity`。

### Python 调用示例

下面接在本文件“从已保存研究集合开始”示例之后运行，确认 `analysis` 和 `preview` 已成功生成：

```python
from pathlib import Path
from quantlab.portfolio import (
    PortfolioBacktestError, run_equal_weight_benchmark,
    save_portfolio_run, list_portfolio_runs, load_portfolio_run,
)

benchmark = None
benchmark_error = None
try:
    benchmark = run_equal_weight_benchmark(preview, factor_name="momentum_20")
except PortfolioBacktestError as error:
    benchmark_error = error

# 本示例策略与基准都使用默认交易/指标参数；若策略自定义了参数，基准必须相同。
record = save_portfolio_run(
    analysis, Path("data/portfolio_runs"), name="20 期动量首次实验",
    benchmark=benchmark, benchmark_error=benchmark_error,
)
scan = list_portfolio_runs(Path("data/portfolio_runs"))
print(scan.records)   # 按保存时间倒序排列的可读记录
print(scan.issues)    # 损坏或不支持的记录，原文件不会被修改

loaded = load_portfolio_run(Path("data/portfolio_runs"), record.run_id)
print(loaded.strategy.performance.cumulative_return)
print(loaded.benchmark_status)
print(loaded.warnings)
```

基准状态明确区分：`complete` 为完整成功；`not_run` 为未提供基准；
`unavailable` 为尝试失败。最后一种仍保留完整策略，但只记录白名单原因、
日期和 ETF 代码，不保存异常全文、机器路径或凭证。不能同时提供成功基准和失败原因。

### 读取历史的边界

读取与列出都不访问原行情、研究集合或外部接口，不计算因子、不回测，也不调用
当前绩效公式。原文件移走后仍可读。当前代码版本与档案不同只产生提示，
不会把历史运行时间、代码版本或结果改写成今天的值；不支持的档案格式则拒绝读取。
保存当前结果时会复核绩效；若源码在运行中变化，或结果来自其他代码版本，
会拒绝新保存，避免用新公式给旧结果重新背书。

内容指纹用于发现文件损坏，**不是防伪签名、加密或盈利证明**。读取时的结构及
账务核对也不是完整策略重放认证，不能证明协同修改的数据真实或当时可得。
档案包含研究数据，应自行备份且不要随意分享；Git 忽略规则不是备份或访问控制。
目录中的临时文件不列为成功记录，已有档案（包括同名符号链接）不会被覆盖。

## 保存实验与历史实验界面

在“因子研究”中，当前研究和历史档案现在分为两个独立入口：

1. **当前研究 → 组合回测**：设置参数、运行成功后，在“保存本次实验”中输入
   实验名称，点击“保存实验”。运行本身不会写档案，空名称不能保存。
2. **历史实验**：选择已保存的实验，查看当时的指标、资金与回撤曲线、
   基准比较、交易明细和原始参数。即使原集合或行情文件移走，历史入口仍可使用。

本地档案写入 `data/portfolio_runs/`。同一次运行重复点击保存只提示已有记录，
不覆盖、不另名复制；需要新实验时重新运行。目录权限或保存校验失败时，当前结果保留。
档案较大时列表读取会更慢，因为每次刷新都核验文件；本步未引入缓存或分页。

历史视图只读取档案中的值，展示其自己的基准及当时的年化/无风险利率假设，
不会使用当前会话的基准、重新运行策略或替换当前结果。参数变更仍会清除当前
旧结果，但不清除已保存的历史。基准“未运行”和“运行失败”有不同提示，
不可用时不展示收益差；旧代码版本会显示警告，不修改原档案。

无法读取或损坏的档案从列表排除并提示数量，不自动删除，也不显示底层异常
可能携带的私人路径。公开临时模式只读写同一会话的临时档案，不能作为持久
备份，也不会读取本地个人档案或其他会话。访问验证在任何目录读取之前执行。

## 单次实验包导出

操作：进入“因子研究 → 历史实验”，选中已保存的实验，在“导出本次历史实验”
中点击“下载实验包（ZIP）”。未保存的当前回测不提供此入口；请先主动保存。
文件名使用原运行编号，不使用实验名称拼接文件路径。

压缩包内容：

- `archive.json`：原档案逐字节备份，包括原运行时间、代码版本、指纹和独立快照。
- `metadata.json`：原参数、数据来源、策略/基准身份、失败状态、表类型和 CSV 约定。
- `README.txt`：中文字段、单位、缺失值和 Excel 查看说明。
- `strategy/`：八张输入/结果表，以及 `performance.csv`（收益/净值/回撤）和
  `metrics.csv`（五项指标及未定义原因）。
- `benchmark/`：仅成功基准才有，表结构对应策略，但没有因子快照。
  未运行或失败基准在说明与元数据中明确记录，不输出伪造的成功表格。

## 分年份表现检查

当前组合回测结果和历史实验结果均增加“分年份表现检查”。它只读取该份结果的
完整资金曲线，临时派生年度表，不重新运行因子、交易或原全区间绩效分析。
历史页面明确标注“当前版本依据已保存资金曲线临时计算”；原指标、JSON 档案
和 ZIP 实验包不加入或覆盖年度统计，旧代码版本档案也可按此口径查看。

### 如何理解表格

- **策略区间收益**：该年度片段末资产 ÷ 收益起算资产 − 1。第一年从研究首个
  资产观测起算；后续年份连接该年首条观测之前的最后一个资产点，避免漏掉
  新年首个收益区间。按收益区间结束年份归属，保留热身、空仓和交易成本影响。
- **年内最大回撤**：在上述起算点加该年观测形成的片段内，重新累计峰值，
  取资产相对峰值回撤的最小值，以负数表示。不沿用更早年份的历史最高点，
  也不是把原全程回撤曲线按年切片。
- **基准区间收益**：用这份实验自己的全池等权买入持有基准，以同一边界计算。
  先验证完整日期轴、数据身份、成本及比较口径一致，不截取日期交集。
- **收益差（百分点）**：`100 × (策略区间收益 − 基准区间收益)`。例如 10% 与
  6% 相差 4 个百分点，不是二者收益率相除，也不是风险调整 alpha。
- **年度覆盖日期与计算口径**：展开后可核对收益起算日、年内首/末观测日、
  年内观测数及收益区间数。收益起算日可能属于上一年；后续年份即使只有
  一个观测，只要存在此前资产点，也有一个收益区间。

只包含一个研究起始资产点时，区间收益与局部回撤均留空，不伪装成零；有多个
相同资产点的现金路径则是真实 0。没有任何观测的年份显式留空。若两条相邻
资产记录之间跳过整年，后续行展示的是实际观测跨度收益，并警告“跨整年缺口，
不是单年收益”；不插值、不填零、不把更早观测冒称上年末。

全部行都是已有研究日期轴上的片段，不认证权威交易日历或完整全年覆盖。
短年份不外推成年化收益，各年收益率也不能直接相加。年度差异只是样本内
描述，不能当作参数稳定性、样本外有效性或盈利证明。

## 收益集中度检查

入口位于“当前研究 → 组合回测”的“分年份表现检查”之后；“历史实验”也有同一模块。
它回答的是：**正向资产变化是否主要集中在少数观测区间？** 不自动判定策略好坏。

### 计算口径与阅读方法

对完整资金曲线的相邻观测计算 `资产增量 = 本期总资产 − 上期总资产`，只取大于零的项。
将最高至多 5 项相加，再除以全部正增量之和；不是除以最终净利润，也不是逐笔交易胜率。
表格列出区间起止日、资产增量（元）及占全部正向增量的比例；并列按较早区间优先。

- 例：正增量为 1、2、3、4、5、6 元，前 5 项合计 20 元，全部合计 21 元，
  集中度为 `20 / 21 ≈ 95.24%`。即使另有较大亏损导致最终亏损，该占比仍有定义。
- 只有一个资产观测点，或所有增量均不为正时，显示“不可用”及原因，不写成 0%。
- 只有 1–4 个正增量时全部纳入，说明实际数量和 100% 的原因；不据此自动判定风险高。
- 保留完整日期轴、热身与现金期，不补缺失日期；一个观测区间可能跨多个自然日。
- 金额包含曲线已有的估值变化及成本，不是已实现交易利润。仅适用于当前无外部出入金的

## 按研究池基准涨跌检查表现

这是分市场环境研究的第一小步，位置在收益集中度之后。它回答“研究池基准上涨或下跌的
观测区间里，策略平均表现怎样”，是**同期事后分组**，不是牛熊识别或提前可用的交易信号。
沿用已有成本后全池买入持有基准；基准不是市场指数，仅初始目标等权，之后权重漂移，
并包含余留现金。它不能认证策略适用于真实牛熊市。

### 分组与均值口径

1. 使用各自完整曲线的相邻观测收益 `r = 本期总资产 / 上期总资产 − 1`，不补日期、
   不取两条曲线的交集，第一条资产记录不伪造零收益。实现用等价的“资产差 / 上期资产”
   保留极小的非零变动；无法可靠表达的收益或均值拒绝展示，不丢弃坏区间。
2. 只有基准在两个端点均有正持仓市值时，才依据该区间基准收益的正、负、零分为三组。
   两端均无持仓记为“基准现金区间”；从无持仓变为有持仓记为“基准首次建仓区间”。
   这两类只统计数量，均值留空，避免把现金不动视为市场震荡、把建仓成本视为市场下跌。
   分类与策略自身是否持仓无关；一次买入持有基准出现退出或再次建仓时拒绝分组。
3. 三组分别显示区间数量、策略平均区间收益、基准平均区间收益、平均收益差（百分点）。
   均值为各区间收益的**算术平均**，收益差为策略与基准逐区间收益差的平均乘以 100；
   不按自然日跨度加权，不是累计收益、年化收益或 alpha。
4. 例如某组两个不连续区间，策略收益为 `+10%、−5%`，基准为 `+2%、+4%`：
   策略均值为 `2.5%`、基准均值为 `3%`、差为 `−0.5` 个百分点；不是复利收益 `4.5%`。
5. 五类数量之和等于完整曲线观测点数减一。空组数量为 0，收益留空而非 0；真实均值
   恰好为零时才显示零。界面中的灰色 `None` 表示缺失或不参与统计，不是零。
   只有一条记录或没有持仓→持仓区间时另行说明不可用。

同组区间可以不连续，因此不拼接净值线，不计算组内最大回撤、夏普或交易胜率。
小样本、日期缺口、数据当时可得性与静态研究池等限制仍然存在；不是样本外检验。
基准缺失或口径不一致时，整个比较块不可用，原策略结果保留；不借用其他实验的基准。

## 先有历史，再产生目标

设因子回看期数为 L，调仓间隔为 K，研究日期轴从位置 0 开始。
固定信号位置为 `L, L + K, L + 2*K, ...`，不是按自然日或每月调仓。

例如使用 20 期动量、每 20 期调仓：

- 位置 0～19 为热身，尚未生成调仓决策。
- 位置 20（第 21 个研究日期）收盘后，第一次按因子值选择 ETF。
- 若有下一日期，计划在位置 21 开盘执行，不能在信号当日开盘成交。
- 下一次信号固定在位置 40。即使位置 20 因数据不足跳过，也不推迟到
  “第一次有足够数据之日”重新计时。

20 期均线偏离和价格最大回撤使用 L=19：第 20 个研究日期收盘后发出首个信号，
第 21 个研究日期开盘才可执行，随后仍按固定 K 间隔。两者都不是区间涨幅，
也不意味着更好的投资。滚动价格回撤与组合绩效区的全区间最大回撤分开计算。

20 期成交量变化使用 L=20、21 条成交量，历史均量不含当期；与 20 期动量一样，
最早第 21 条收盘后信号、第 22 条开盘执行。零分母不参与筛选，但不会移动
策略固定调仓日期或基准计划建仓日。真实零量的有效 -100% 可参与排名，
下一期能否成交仍由引擎单独检查，不由因子有效性认证。

20 期趋势效率同样使用 L=20、21 条收盘价，最早第 22 条开盘执行。
结果在 -1 到 1 之间，恒价与首尾相等按定义为有效零；默认按有符号值降序，
不把持续下跌的 -1 取绝对值排到前面。它是路径效率，不是收益率。
缺失或数值不可用不改变固定信号日期及自身基准锚点。

已支持的价格因子都需要 L+1 个连续窗口价格点；有效 ETF 不足
N 只时，没有目标配置。研究日期轴由现有研究集合提供，不自动补成官方
交易日历，也不因某个日期有缺失而压缩日期轴。

## 决策状态

| 状态 | 含义 | 是否有目标行 |
| --- | --- | --- |
| `PENDING` | 有效 ETF 足够，且存在下一研究日期，等待后续引擎执行 | 恰好 N 行 |
| `SKIPPED_INSUFFICIENT_FACTORS` | 有效 ETF 不足 N，跳过本次调仓 | 无 |
| `EXPIRED` | 有效 ETF 足够，但信号已经在最后一个研究日期 | 恰好 N 行，仅供解释 |

没有下一研究日期时，`execution_date` 为 `NaT`。最后一天若也不足 N，
状态仍是“有效因子不足”，不覆盖为“过期”。

“跳过”不是清仓指令。后续引擎应保留原现金和持仓，并照常对持仓估值。
初始资金也会在热身及未成功建仓期间保持现金；第 1 步只记录安排，
尚未计算这条现金路径。默认初始现金 100,000 元来自既有交易配置。

## 排序和目标权重

- 动量默认从大到小，选择过去价格动量较强的 ETF。
- 波动率默认从小到大，选择过去价格波动较小的 ETF。
- 均线偏离默认从大到小，选择当前价格相对 20 条收盘价均值位置较高的 ETF。
- 价格最大回撤默认从大到小，零或负数越接近 0 越靠前，仅表示窗口内历史回撤较浅。
- 成交量变化默认从大到小，仅表示相对自身此前均量的放量更明显，不是资金净流入或收益预测。
- 趋势效率默认从大到小，越接近 +1 表示向上方向更连贯；保留符号，不按绝对趋势强度排序。
- `ascending=True/False` 可明确覆盖排序方向；低波动不意味着未来必然
  低风险，高动量也不意味着未来必然上涨。
- 用未经显示舍入的原始因子值排序。有效的 0 和负值也参与，缺失及
  无效值不参与，不将其填成 0。
- 原始值相同时，按六位 ETF 代码升序确定先后，并且恰好选 N 只。
  若第 N 与第 N+1 只原值相同，`cutoff_tie=True` 并记录提示；代码顺序
  只是确定性规则，不表示投资优劣。
- 每只目标权重为未经舍入的 `1/N`。这是配置目标，不是已经成交后的
  实际权重；后续整手约束、费用和余款都会使实际权重产生偏差。

### 为什么 10 万元会剩下 1,990 元？

假设两只 ETF 价格都是 10 元，每手 100 份；申请各买 5,000 份。
比例佣金和滑点为 0，每笔最低佣金为 5 元，初始可用现金为 100,000 元。

1. 每只完整需求为 `5000 × 10 + 5 = 50005` 元，两笔合计 100,010 元，
   超过可用现金，不能直接各买 5,000 份。
2. 两笔完整需求相同，所以同时获得 50,000 元的独立含费预算。
3. 每只最多买 4,900 份，支出 `4900 × 10 + 5 = 49005` 元。
4. 两笔共支出 98,010 元，余款 `100000 − 98010 = 1990` 元留作现金。

即使余款还能支持某只多买一手，也不二次分配，避免代码排在前面的 ETF
优先用完余款。因此目标等权，不意味着扣费后的实际权重精确等权或满仓。

### 分配和输入规则

对正申请份额 d、含滑点买价 p，完整需求为：

`need = d × p + max(d × p × 佣金率, 最低佣金)`

现金足够时买足全部申请；不足时，各自预算为
`cash × need / 全部 need 之和`。先确定所有预算，再按整手买入；输入
字典的先后顺序不影响结果，输出按 ETF 代码排序。零申请无需开盘价，
实际可买数量为零时不收最低佣金。

- 独立求数量函数允许最大份额不是整手，按不超过上限的整手寻找。
- 多资产分配函数要求申请已经是整手差额；不默默替调用方修正非整手申请。
- 正申请必须有正的有限开盘价；金额、费率、数量和方向均在入口校验。
- 大申请量使用整数手数二分查找，不是一手一手往下减，因此不会因申请
  了极大份额而进入超长循环。
- 不把价格或费用四舍五入到分，不用相对或绝对容差放宽买入预算。
  余额归整容差不是可借用的资金；哪怕只差一点，也不能多买一手。
- 溢出、非零滑点/佣金被数值精度完全吞掉、最终份额无法精确参与金额
  运算，或分配舍入使合计支出超过现金时，抛出 `PortfolioBacktestError`
  （`reason="numeric_range"`），不返回看似成功的部分配置。

第 3 步引擎对结果表执行 int64 份额范围限制；本预算模块接受 Python 整数
上限，但不是承诺任意巨大的成交数量都能可靠计算。

## 第 3 步：现金、订单与每日估值

新增 `src/quantlab/portfolio/engine.py`，提供内部函数 `simulate_portfolio`。
`types.py` 新增 `PortfolioBacktestResult`，并集中定义六张表的字段及类型。
`selection.py` 仅改为引用这套统一结构，原有筛选规则不变。

引擎每天完成以下工作：

1. 查找应该在当天开盘执行的前日配置，检查原持仓及目标 ETF 的开盘价。
2. 根据开盘交易前总资产计算一次整手目标；先卖出多余份额或退出的资产。
3. 对待买差额同时分配含费预算，再买入。每侧按代码升序记录，不抢占预算。
4. 检查实际成交资产是否为零成交量；没有数量差额或实际买不到一手时不误报。
5. 用当日收盘价估值持仓，核对现金、份额与总资产，完成后才接受当天记录。

目标不按扣费后的总资产反复重算；保留的 ETF 只交易数量差额，不全部卖掉
再买回。信号日不开仓，热身阶段的全现金也保留在资金曲线中；期末不强制平仓。

### 三日手算账本

假设初始资金 1,000 元，每手 10 份，佣金、税、滑点全为 0。
A=510300，B=159915，C=512000；每次选两只，目标各占一半。

- D0 收盘选择 A/B；D1 开盘价分别为 10/20 元。
  因整手限制，买 A 50 份、B 20 份，余款 100 元。
- D1 收盘价变为 A=11、B=18；当日收盘选择 B/C。
- D2 开盘价 A=12、B=20、C=5，交易前资产为 1,100 元。
  卖掉 A 的 50 份，保留 B 的 20 份，买入 C 的 110 份。
  D2 收盘价与开盘价相同。

| 日期 | 期末现金 | A 份额 | B 份额 | C 份额 | 持仓市值 | 总资产 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| D0 | 1000 | 0 | 0 | 0 | 0 | 1000 |
| D1 | 100 | 50 | 20 | 0 | 910 | 1010 |
| D2 | 150 | 0 | 20 | 110 | 950 | 1100 |

D1 的成交记录先买 B，现金变为 600，再买 A，变为 100；D2 先卖 A，
现金变为 700，再买 C，变为 150。订单和成交按真实模拟顺序保存，不能
最后按代码全局重排，否则“成交后现金”就无法顺着行核对。

### 返回哪些内容

- `decisions`：计划、跳过、过期与执行流程状态。
- `targets`：信号日的数值目标，按日期/代码输出独立副本。
- `orders`：申请量、实际量、未成交量和原因；区分全部成交、部分成交与拒单。
- `trades`：只有正成交数量的记录，含佣金、卖出税、滑点金额、成交后现金及份额。
- `positions`：每天每只 ETF 的份额、市值和实际权重，包括空仓代码。
- `equity_curve`：每日现金、持仓市值、总资产、净值、累计收益、累计佣金税费及累计滑点。

拒单没有成交 ID，也不收费。滑点已经体现在成交价，现金不重复扣除；
累计滑点单独展示，与累计佣金税费分列。数值目标不等于实际持仓权重。

### 缺失与失败边界

跳过调仓时保留持仓并继续估值。原持仓缺收盘价仍须失败；空仓资产缺价
则保留空收盘价，市值和权重为 0，不做 `0 × NaN` 运算。

缺必需开盘价、持仓缺收盘价、实际成交资产零成交量、部分损坏的 OHLCV 行、
负卖出净收入、数值溢出或数量越界都会抛出结构化错误。运行时错误带日期、
相关代码与原因；整个运行失败，不返回部分资金曲线，也不修改输入。

补充的保守限制：如果费用等使总资产恰好耗尽为 0，权重和后续指标无法按
当前口径定义，报 `non_positive_equity`，不构造虚假权重。微小的正现金不会
被抹成 0；`1e-9` 容差仅处理运算后的微小负余额，不能用来多买一手。

正成交量不证明能够按开盘价成交。复权价下的份额、静态 ETF 池、研究日期轴
等原有限制仍然存在，本引擎不是实盘可成交性证明。

### 为什么“0”和“无法计算”不一样

一个收益率需要两个资产观测值；样本波动率至少需要两个收益率。

| 输入情况 | 累计/年化收益 | 年化波动率 | 夏普比率 | 净值与最大回撤 |
| --- | --- | --- | --- | --- |
| 仅 1 个资产观测 | `None`，没有收益区间 | `None` | `None` | 净值 1，最大回撤 0 |
| 2 个资产观测 | 可以计算 | `None`，仅一个收益率 | `None` | 可以计算 |
| 至少 3 个观测、始终全现金 | 0 | 0 | `None`，波动为零 | 净值始终 1，最大回撤 0 |
| 至少 3 个观测、收益有足够波动 | 可以计算 | 可以计算 | 可以计算 | 可以计算 |

夏普沿用既有阈值：**日收益率样本标准差不高于 `1e-15` 时未定义**，
比较的不是年化波动率。固定正收益也可能没有足够波动，不能把夏普写成无穷大。
最大回撤沿用原指标的符号：例如 `-0.12` 表示相对历史最高净值下跌 12%。

只有一个资产观测时，`daily_returns` 是带日期索引的空浮点序列；
其他情况下包含从第二个研究日期开始的相邻期收益率，不给首日伪造一个 0 收益。
期数按研究日期轴而非自然日计，日期轴与复权数据的原有限制仍保留。

### 费用和热身期没有丢失

- 首次交易期收益为 -0.01%，这笔费用在净值与回撤中可见。
- 年化使用全部 22 个收益区间：`1.0044 ** (252 / 22) - 1`。

3. **区分日期轴。** 两只 ETF 在热身期同一天无记录时，用户提供的日期轴
   仍保留这一天的现金估值；行情并集轴会遗漏该日，两者不能当成同一输入。
4. **检查旧模块边界。** 解析第一阶段数据、指标、策略、回测和配置模块的
   导入语句，确保没有反向引入 `portfolio` 或 `factors`。
5. **独立对账。** 45 种组合覆盖五个因子、默认/正/反方向、不同 N/K、
   手数、佣金下限、卖出税与滑点。逐笔用成交额、佣金和税重算现金与份额，
   每日检查市值、总资产、权重、累计费用及完整区间收益；不复用引擎内部记账函数。

这些都是合成数据的自动化验收，不是策略有效性、真实可成交性或盈利证明。

### 从已保存研究集合开始

以下代码放在 Python 脚本内运行；`set_id` 替换为已保存研究集合的实际编号。
该集合需要至少两只 ETF；路径也应指向你实际保存集合的目录。

```python
from pathlib import Path
from quantlab.data.research_storage import load_research_set
from quantlab.portfolio import (
    PortfolioBacktestError, PortfolioConfig,
    analyze_portfolio_result, run_factor_portfolio,
)

preview = load_research_set(
    Path("data/research_sets"), "替换为实际研究集合编号",
).preview

try:
    result = run_factor_portfolio(
        preview, factor_name="momentum_20",
        config=PortfolioConfig(top_n=2, rebalance_interval=20),
    )
    analysis = analyze_portfolio_result(result)
except PortfolioBacktestError as error:
    # 缺少必要价格等错误时，没有完整期间的成功结果。
    print(error.reason, error.date, error.symbols, str(error))
else:
    print(analysis.performance.cumulative_return)
    print(analysis.performance.unavailable_reasons)
    print(analysis.performance.net_value)
    print(result.orders)   # 包括买不足或买不到的申请
    print(result.trades)   # 只有实际模拟成交及费用
```

阅读结果时，先看 `decisions` 的跳过/过期原因和 `metadata["warnings"]`，
再看目标与实际持仓差异，最后查看完整资产曲线及绩效。不能仅凭一个收益数字判断策略。
