# QuantLab iFinD 自然语言查询设计

## 1. 目标与定位

QuantLab 增加一个面向普通投资者的“iFinD 智能查询”功能。用户可以用
自然语言描述需要的数据，系统将问题转换为受控的结构化查询，在用户
确认查询对象、指标和时间范围后，再由服务器调用 iFinD。

首版目标是让受邀普通用户完成以下闭环：

```text
邀请码注册或登录
→ 选择快捷查询或输入自然语言问题
→ 查看并确认查询条件
→ 调用 iFinD
→ 查看表格、图表和解释
→ 下载结果或用于 QuantLab 分析
```

本功能是受控数据查询入口，不是通用 AI 编程工具，也不是开放的 iFinD
命令终端。

## 2. 首版范围

### 2.1 支持的查询类型

首版只允许以下四类白名单查询：

1. **历史行情**
   - ETF、A 股和主要指数；
   - 日线开盘价、最高价、最低价、收盘价和成交量；
   - 不复权、前复权和后复权；
   - 单次最多 10 个标的，最长 10 年。

2. **标的表现比较**
   - 累计收益率、年化收益率、年化波动率、最大回撤和夏普比率；
   - 净值曲线和回撤曲线；
   - iFinD 只提供原始行情，绩效指标继续由 QuantLab 现有计算模块生成。

3. **指数成分**
   - 指定指数在指定日期的成分；
   - 证券代码、名称，以及接口返回时的权重；
   - 首版不支持一次请求大量历史调仓截面。

4. **基础财务指标**
   - 营业收入、净利润、每股收益、净资产收益率、毛利率、资产负债率和
     经营现金流；
   - 支持单家公司历史趋势，以及最多 10 家公司的横向比较；
   - ETF 不直接查询公司财务指标。

### 2.2 明确不做

首版不实现：

- 用户输入或执行任意 iFinD 函数、Super Command、代码或 SQL；
- AI 自行扩大证券范围、时间范围或指标范围；
- 白名单外的自由数据检索；
- AI 自动执行交易或连接券商；
- 管理员角色、管理后台、计费后台或公开注册；
- 在页面展示令牌、内部权限规则、JSON、缓存机制或审计细节；
- 替换或改写现有收益、风险、回测与交易复盘计算模块。

## 3. 用户体验与页面结构

### 3.1 明确入口

左侧导航的“分析”分组增加独立页面 **iFinD 智能查询**。

以下页面可以提供快捷按钮，但都进入同一个智能查询页面：

- “添加资产数据”页面的“从 iFinD 获取”；
- “投资表现”页面的“使用 iFinD 查询”。

页面不重复实现查询逻辑。

### 3.2 页面内容

页面由三部分组成：

1. **快捷查询**
   - 行情查询；
   - 标的比较；
   - 指数成分；
   - 基础财务。

2. **自然语言提问**
   - 一个清晰的提问输入框；
   - 与白名单能力一致的示例问题；
   - 输入后先解析，不立即消耗 iFinD 调用。

3. **查询确认卡**
   - 查询对象；
   - 数据类别或指标；
   - 时间范围；
   - 复权方式等必要口径；
   - 数据来源；
   - 预计接口调用次数；
   - “确认并查询”和“修改条件”操作。

后台的白名单、权限、限流、缓存与审计规则不在普通用户页面展示。

### 3.3 查询结果

成功后按数据类型显示：

- 结果摘要；
- 表格；
- 适用时的趋势图、净值曲线或回撤曲线；
- 自然语言解释；
- 数据来源、查询口径和获取时间；
- “下载结果”和“用于 QuantLab 分析”入口。

结果解释不得捏造缺失数据，也不得把描述性分析表达为确定的投资建议。

## 4. 总体架构

```text
Streamlit 页面
    ↓
SmartQueryApplicationService
    ├── LanguageModelGateway
    │       ↓
    │   OpenAI API
    ├── QueryRegistry / QueryValidator
    ├── QueryConfirmationStore
    ├── QueryUsagePolicy
    └── IFindQueryGateway
            ↓
        iFinD QuantAPI
            ↓
        ResultNormalizer
            ↓
    QuantLab 数据与计算模块
```

页面只调用 `SmartQueryApplicationService`，不直接调用 OpenAI、iFinD 或
现有计算函数。应用服务负责协调解析、校验、确认、执行、保存和结果
格式化，各组件可以独立替换和测试。

## 5. 组件设计

### 5.1 `LanguageModelGateway`

首版接入 OpenAI API，只负责把自然语言问题解析为固定结构的查询草案。
它不持有 iFinD 凭证，也不能直接执行查询。

结构化输出至少包含：

- 查询类型；
- 标的及其类型；
- 指标；
- 开始日期和结束日期，或指定截面日期；
- 周期与复权方式；
- 尚缺少、需要向用户补充的参数。

若问题存在重要歧义，系统向用户追问，不擅自补充会改变结果的条件。
Gateway 保持可替换，未来切换其他语言模型时不修改页面、查询白名单和
iFinD 连接层。

### 5.2 `QueryRegistry`

集中登记每一种允许查询的：

- 稳定查询类型标识；
- 允许的参数和指标；
- 必填条件和默认值；
- 证券数量、日期跨度和数据量限制；
- 对应的 iFinD 查询适配器；
- 对应的结果标准化与展示方式。

AI 返回的查询类型必须存在于 Registry。页面快捷查询也使用同一份
Registry，避免快捷表单和自然语言入口产生两套规则。

### 5.3 `QueryValidator`

执行确定性校验，包括：

- 证券代码和证券类型；
- 日期顺序和最大跨度；
- 指标是否在白名单；
- 数量上限；
- 复权、频率和报告期是否合法；
- 查询参数是否完整。

校验失败时不调用 iFinD。任何用户文本都不能被直接拼接成可执行命令。

### 5.4 `QueryConfirmationStore`

解析通过后生成一次性查询草案，并保存：

- 草案编号；
- 所属用户；
- 原始问题；
- 已校验的结构化参数；
- 预计调用次数；
- 创建和过期时间；
- 确认状态。

只有所属用户确认尚未过期的草案后才执行。执行时读取服务端保存的已
校验参数，不接受浏览器重新提交的任意参数，避免绕过确认卡。

### 5.5 `IFindQueryGateway`

封装首版白名单查询对应的 iFinD QuantAPI 调用。它与历史行情
`IFindQuantAPIProvider` 共用底层认证和 HTTP 传输能力，但不把通用查询
能力暴露给页面或语言模型。

每一种查询通过明确的适配器实现，例如：

- `HistoricalMarketQuery`；
- `InstrumentComparisonQuery`；
- `IndexConstituentQuery`；
- `FundamentalMetricQuery`。

Gateway 不接受任意函数名或任意命令字符串。

### 5.6 `ResultNormalizer`

负责把外部结果转换成稳定的数据对象：

- 历史行情进入 QuantLab 现有标准行情结构；
- 表现比较复用现有收益与风险计算模块；
- 指数成分进入统一成分表结构；
- 财务数据进入统一的证券、报告期、指标、数值结构。

页面只消费标准结果，不解析 iFinD 原始响应。

## 6. 查询流程

### 6.1 解析阶段

1. 用户选择快捷查询或输入自然语言问题。
2. 应用服务检查登录状态和输入长度。
3. `LanguageModelGateway` 生成查询草案；快捷查询直接生成相同结构。
4. `QueryRegistry` 和 `QueryValidator` 校验草案。
5. 条件缺失时返回自然语言追问。
6. 条件完整时创建确认记录，并在页面展示确认卡。

解析阶段不会调用 iFinD。

### 6.2 执行阶段

1. 用户点击“确认并查询”。
2. 服务端验证草案所属用户、有效期、确认状态和额度。
3. 查询有效缓存；完整命中时直接返回标准结果。
4. 未命中时由白名单适配器调用 iFinD。
5. 校验并标准化返回数据。
6. 保存原始响应、标准结果、来源、口径、获取时间和数据版本。
7. 需要指标时调用现有 QuantLab 计算模块。
8. 返回表格、图表数据和解释所需的结构化结果。

## 7. 普通用户与邀请制内测

首版产品只设计一种可见角色：**普通用户**。

- 用户通过有效邀请码注册；
- 用户登录后才能进行智能查询；
- 用户只能查看自己的问题、确认记录、查询历史和保存结果；
- 公共市场数据缓存可以安全复用，但其他用户的行为和记录不可见；
- 不开发管理员账户或管理后台；
- 邀请码生成、账户停用和额度调整暂由服务端配置或维护脚本完成；
- 后续转公开注册时替换注册策略，不重写查询和数据模块。

在 iFinD 授权明确允许多用户间接访问、缓存与展示之前，真实 iFinD
查询不得向受邀用户开放；此限制由服务端配置执行，不在页面展示内部
授权细节。

## 8. 保存、缓存与额度控制

### 8.1 保存边界

保存以下审计信息：

- 用户问题；
- 模型解析结果；
- 最终确认参数；
- 查询类型和数据来源；
- 调用时间、耗时、状态和错误分类；
- 结果版本和缓存键；
- 接口调用次数。

令牌、密码、完整认证响应和其他敏感内容不得保存。

### 8.2 缓存

- 相同的公共数据查询优先复用未过期缓存；
- 缓存键必须包含查询类型、标的、指标、日期、周期、复权口径和数据源；
- 个人查询记录与公共数据缓存分开；
- 缓存损坏时记录错误并重新获取，不向用户展示技术细节；
- 查询结果用于 QuantLab 分析时复用已保存的标准结果，不重复调用 iFinD。

### 8.3 额度

服务端按普通用户执行：

- 单次查询上限；
- 每日和每月调用上限；
- 请求频率限制；
- 并发限制；
- 外部接口失败后的有限次数重试。

页面仅显示用户需要知道的可用提示，例如“请求较频繁，请稍后再试”，
不展示内部限流、缓存和审计实现。

## 9. 凭证与安全

OpenAI 和 iFinD 凭证只从服务器环境变量或部署平台的密钥管理服务读取。

实现必须保证：

- 凭证不进入浏览器、页面状态、下载文件或日志；
- 凭证不写入源码或提交到 Git；
- 日志和异常在写入前脱敏；
- OpenAI 不能直接访问 iFinD 凭证或执行查询；
- 页面不能提交函数名、命令文本或越过 Registry 的查询类型；
- 查询确认记录只能由所属用户使用，且只能执行一次；
- 所有服务端权限与额度检查在执行时重新验证，不能只依赖页面控制。

这些原则通过后台代码、配置和测试强制执行，不在普通用户页面呈现。

## 10. 错误处理

用户页面只显示自然语言错误：

- 无法理解问题：“我还不能确定查询对象或时间范围，请补充以下信息。”
- 不支持的请求：“当前暂不支持这类查询，可以尝试以下查询方式。”
- 无数据：“未找到符合条件的数据，请检查证券代码或日期范围。”
- 服务暂时不可用：“数据服务暂时无法连接，请稍后重试。”
- 请求受限：“请求较频繁，请稍后再试。”
- 登录或草案失效：“本次查询确认已失效，请重新提交问题。”

页面不显示 Python traceback、HTTP 响应、模型 JSON、内部函数名或令牌
状态。技术错误写入脱敏日志，并使用稳定错误分类供排查和统计。

## 11. 数据结构建议

首版至少需要以下持久化实体：

- `users`：普通用户身份和状态；
- `invites`：邀请码、使用状态和有效期；
- `query_drafts`：待确认的结构化查询草案；
- `query_runs`：执行记录、用量、状态和错误分类；
- `query_results`：结果位置、版本、来源和缓存键；
- `usage_counters`：用户日/月调用计数。

用户密码必须采用成熟密码哈希方案保存，不能明文保存。数据层通过
Repository 接口隔离，使首版本地存储未来能够迁移到网站数据库，而不
修改页面和查询核心逻辑。

## 12. 实施顺序

本设计依赖已确认的 iFinD QuantAPI Provider 设计。建议按以下顺序开发：

1. 完成可测试的 iFinD HTTP 客户端和历史行情 Provider；
2. 建立白名单 Registry、结构化查询对象和确定性校验；
3. 建立 OpenAI `LanguageModelGateway` 并使用模拟查询执行端测试；
4. 建立查询确认、缓存、用量和审计服务；
5. 接入四类 iFinD 白名单查询适配器；
6. 增加普通用户邀请注册、登录和数据隔离；
7. 建立 iFinD 智能查询页面及 QuantLab 跳转入口；
8. 在取得正式权限后运行受控集成测试，再决定是否向受邀用户开放。

## 13. 测试设计

默认自动测试不得访问 OpenAI 或 iFinD，使用模拟 Gateway 和模拟数据。

至少覆盖：

- 四类支持问题均能生成正确的结构化草案；
- 歧义或缺少条件时返回追问且不调用 iFinD；
- 白名单外查询、任意命令和提示注入不能绕过 Registry；
- 证券、指标、数量、日期和复权口径校验；
- 未确认、过期、他人所有或已执行草案不能执行；
- 确认后只执行服务端保存的已校验参数；
- 缓存命中不重复调用 iFinD；
- 用户日/月额度和请求频率限制；
- 公共缓存可复用，查询历史和个人结果保持隔离；
- OpenAI 和 iFinD 故障、超时、空数据和响应字段变化；
- 令牌与敏感信息不会出现在页面、异常或日志；
- 绩效比较继续调用现有 QuantLab 指标模块；
- 更换语言模型或查询 Gateway 不影响页面和 Registry。

增加默认跳过的 OpenAI、iFinD 和端到端真实集成测试。只有在服务器明确
设置集成测试开关和专用凭证时才运行，避免普通测试消耗接口额度。

## 14. 验收标准

首版完成时，受邀普通用户能够：

```text
注册并登录
→ 打开 iFinD 智能查询
→ 选择快捷查询或输入自然语言问题
→ 查看并修改查询确认卡
→ 确认调用
→ 查看表格、图表和自然语言解释
→ 下载结果或进入 QuantLab 分析
→ 查看自己的查询历史
```

同时满足：

- 白名单外请求不会调用 iFinD；
- 用户未确认前不会调用 iFinD；
- 相同公共查询优先复用缓存；
- 普通用户之间的数据和记录相互隔离；
- 页面不暴露后台原则、凭证或技术错误；
- 现有行情处理、收益风险、回测和复盘模块不被破坏；
- 无真实外部凭证时，应用仍可启动并完成全部模拟测试。

## 15. 已知限制与上线前条件

- iFinD 实际函数、字段、权限、频率和历史范围以最终账号权限及正式接口
  响应为准；
- OpenAI 模型只能帮助理解问题，最终查询边界由确定性白名单控制；
- 首版不覆盖自由研究、任意指标或通用 Super Command；
- 自然语言解释只基于已返回数据，不构成投资建议；
- 邀请制用户共享服务器 iFinD 能力之前，必须确认合同允许多用户间接
  访问、缓存、结果展示与下载；
- 公开注册、管理员后台、商业计费和更复杂的数据权限需要后续独立设计。
