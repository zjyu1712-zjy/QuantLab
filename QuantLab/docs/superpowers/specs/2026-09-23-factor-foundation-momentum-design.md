# 轻量因子接口与 20 期动量设计

日期：2026-09-23。状态：对话方案已确认；本书面设计待用户审阅。
本文件是设计约定，不表示业务代码已经实现或验收通过。

## 1. 目标与已确认范围

QuantLab 是金融专业本科生使用的本地个人研究平台，不连接券商、不自动
交易。用户要求逐步学习、解释每一步，不能一次实现整个第二阶段。

多 ETF 固定版本、日期对齐和研究快照已经具备。本小步在它们之上建立
可复用的轻量因子计算层，并交付第一个 `momentum_20`：20 期价格动量。
成功标准是：同一研究输入产生可解释、可核对的逐 ETF 因子序列，数据
不足时说明原因，输入版本与公式版本可追溯，既有单 ETF 功能不受影响。

用户已确认以下方向：

- 使用已校验研究集合，不修改原行情或快照。
- 公式为当前收盘价除以 20 期前收盘价，再减 1。
- 按研究集合日期轴计数，不按自然日、不跳过缺失日期。
- 当前与此前 20 期共 21 条记录必须全部有效；否则留空。
- 输出因子值、有效状态，以及公式、周期、版本、口径与输入指纹。
- 先实现计算、测试和说明，不增加界面、排名或组合回测。

比较过两种规模：单个公式函数工作量较小，但后续仍需补充统一管理；
轻量统一模块多一层接口约定，能够复用到下一批因子。采用后者，不扩展
成完整研究引擎。

## 2. 不在本步范围内

- 其他具体因子、参数扫描、多因子加权、标准化、排名、前 N 只选取。
- IC、分组回测、因子有效性结论、组合调仓、成交或资金曲线。
- 新页面、自动保存因子结果、结果下载、实验数据库或任务队列。
- 动态执行用户输入公式、插件发现、网络行情下载、自动补历史。
- 官方日历认证、历史逐日可投资股票池或当时可得数据认证。

不新增依赖；复用现有 Python、pandas、NumPy 和测试环境。保留当前项目
目录与分支，保护既有未提交的第一阶段和 iFinD 修改。

## 3. 现有接口与模块边界

当前 `factors/base.py` 已有 `BaseFactor.compute(DataFrame) -> Series`，
`factors/registry.py` 已有显式注册、按名查找和列出名称的占位接口。
仓库内没有具体因子子类或实际因子运行流程。

| 模块 | 本步职责 |
|---|---|
| `factors/base.py` | 因子说明、数值与状态结果、统一调用约定 |
| `factors/registry.py` | 保留显式注册/查找；校验因子类型和名称，拒绝重复 |
| `factors/momentum.py` | 20 期动量及其严格窗口规则 |
| `factors/research.py` | 校验研究快照，按 ETF 调用，合并独立结果并附追溯信息 |
| `factors/__init__.py` | 明确导出接口；不在导入时计算、联网或读文件 |
| 因子测试与说明文档 | 手算、边界、真实快照链路及原功能回归 |

依赖方向为：因子研究服务 → 既有研究预览校验；具体公式 → 因子基础
接口。原数据、指标、策略、回测及第一阶段页面不反向依赖具体因子。

数据流：已载入快照的 `preview` → 独立副本与完整校验 → 逐 ETF 计算
→ 按原日期/代码网格合并 → 返回结果及追溯说明。服务也可接收尚未保存
但有效的 `ResearchSetPreview`，不强制用户先产生磁盘记录。

## 4. 因子约定

### 4.1 定义信息

首个类为 `Momentum20Factor`，唯一注册名为 `momentum_20`。本步固定
周期为 20，不开放可变窗口或自动生成 60/120 期等其他因子。

每个因子通过 `FactorDefinition` 描述：

| 字段 | 本因子含义 |
|---|---|
| `name` | `momentum_20`，与注册名及因子类名称属性一致 |
| `description` | 20 期价格动量 |
| `formula` | `close[t] / close[t-20] - 1`，仅作说明，不执行文本公式 |
| `version` | `1.0`，公式或窗口/缺失规则改变时升级 |
| `required_fields` | `close`、`has_observation`；另要求日期/代码作为行身份 |
| `lookback_periods` | 20，表示当前日期之前的日期轴位置数 |
| `window_observations` | 21，包含当前日期 |
| `direction` | `higher_is_stronger`，更大表示过去价格涨幅更高，并非未来更优 |
| `missing_policy` | `strict_window`，整个窗口必须有观测 |
| `availability` | `after_close`，当日收盘数据可用后计算 |

定义必须有效、稳定且不含运行时间、机器路径或任意环境变量。注册时
拒绝非因子类型、不可实例化的抽象类型、空白/非字符串名称、定义与名称
不一致及重复名称。保留 `register/get/names` 的调用形式；未知名称
保持明确查找失败。使用显式工厂建立每次独立的新注册表，默认只注册
`momentum_20`，不依赖进程内自动发现或共享可变全局注册表。

### 4.2 数值接口与状态接口

保留 `factor.compute(market_data) -> pd.Series` 的调用形式：返回
float64 数值序列，索引与输入行索引完全一致，缺值为 NaN，不返回无穷。

新增统一的 `evaluate(market_data) -> FactorEvaluation`，同时返回
`values` 和 `status` 两个同索引序列。具体因子只实现一套计算；基础类
的 `compute()` 委托 `evaluate()` 获取数值，不能维护两份公式或两套
缺失规则。仓库没有旧具体子类需要迁移；未来自定义子类遵循新约定。

定义对象可以用冻结数据类；其中的 pandas 对象仍然可变。结果必须是
独立副本、不与输入共享可写数据，不将冻结字段误称为表格不可变。

### 4.3 单 ETF 输入

`evaluate/compute` 接收一只 ETF 在共同日期轴上的完整行序列，包括缺失
行。必须有 `date/symbol/close/has_observation`；允许标准化表中的其他
行情列，但本因子不依赖它们。不得先删掉缺失行或取共同观测日交集。

拒绝空表、重复列名、缺少所需列、混入多代码、非六位字符串代码、非唯一
行索引、重复/乱序日期以及非规范日线日期。规范日期使用无时区的零点
`datetime64[ns]`；因子层不重新解析字符串或截断盘中时间。

`has_observation` 必须是无空值布尔列；观测行的 close 必须为有限正数
float64，缺失行的 close 必须为 NaN。全缺失但非空的单 ETF 序列允许
产生全空因子。零成交量不使有效价格观测失效，也不表示能够成交。

此裸序列接口无法证明外部交易日历完整性、真实复权算法或来源真实性；
带追溯的研究调用必须走下一节的研究服务。

## 5. 周期、缺失和数值规则

令 `t` 为研究集合日期轴的零起始位置；每只 ETF 使用同一条轴：

`momentum_20[t] = close[t] / close[t-20] - 1`

例如第 0 个轴日期收盘价为 100，第 20 个轴日期收盘价为 110，且中间
记录完整，则第 20 个位置的值为 0.10。它描述这段历史的价格变化，
不是扣除成本后的策略收益，也不证明因子有预测能力。

每一行只取一个状态，按以下优先级判断：

| 条件 | `status` | 数值 |
|---|---|---|
| `t < 20` | `warmup`：历史长度不足 | NaN |
| `t >= 20` 且 `[t-20, t]` 有任一缺失观测 | `missing_window`：窗口内缺数据 | NaN |
| 完整窗口的运算超出可用数值范围 | `numeric_range`：无法可靠表示 | NaN |
| 其余完整窗口 | `valid`：可计算 | 有限 float64 |

即使早期行缺失，前 20 个位置仍优先记 `warmup`，避免同一行出现两种
不确定原因。缺失可在锚点、中间或当前行，均不得补值、插值、跳过或
向前寻找“最近一个有效价格”。缺失移出 21 行窗口后才能恢复计算。

数值范围异常包括比值上溢/下溢、非有限结果，以及正价输入因舍入而
得到不可能的 `<= -1` 结果；记录 `numeric_range`，不裁剪、不伪装成
精确 -100%。常规计算采用 float64，不增加高精度金融定价依赖。

当前快照只存选定区间，源元数据中的完整历史指纹不是区间外价格数据。
因此必须保留前 20 个位置的热身空值，不回读原文件或隐式扩大范围。
需要某日起有值，应在创建集合时包含足够的更早日期及完整观测。

日期并集可能漏掉“全部 ETF 同时缺失”的日期，所以本步严格称为
“20 期/20 个日期轴间隔”。用户提供日历时仍保留未认证的声明提示。
更换日期轴可能改变锚点和结果；两种日期轴不能被当成同一个研究输入。

## 6. 研究级运行与输出

研究入口接收 `ResearchSetPreview` 和显式注册的因子名称，默认
`momentum_20`。先复制输入，再调用现有 `validate_research_preview`，
核对行情、日期轴、口径、来源、覆盖统计和既有指纹。不信任仅有同名列
的任意 DataFrame，不通过重算并覆盖指纹来修复被修改的输入。

校验后仅重置内部行情副本的行索引标签，再按 ETF 拆分完整日期轴，
调用 `evaluate`。这不改变日期、代码、行顺序、输入身份或调用方索引；
研究预览的行标签不属于数据身份，不能因标签重复而拒绝有效研究集合。
合并时按日期与代码匹配，
不只按行位置拼接；输出保留与输入相同的全部 `(date, symbol)` 行及
顺序，包括热身期和全缺失资产。不跨 ETF 移位，不把空因子当作零。

`FactorRunResult` 包含以下内容：

- `data`：固定列 `date, symbol, factor_value, is_valid, status`。
- `definition`：本次因子的完整定义副本。
- `input_preview_sha256` 与 `alignment_content_sha256`：绑定研究输入。
- `start/end`、完整日期轴声明的副本：含模式、来源、覆盖和日历指纹。
- `adjustment` 及各 ETF 来源身份：保留现有 sources 白名单中除机器
  `processed_path` 外的字段；不附带凭证、个人交易或任意原始元数据。
- `warnings`：继承现有研究输入警告，再追加本因子的适用范围提示。

不把因子列写回 `aligned.parquet`，不改变现有研究集合保存协议；本步
只返回内存结果。`is_valid` 必须与 `status == valid` 一致；有效值有限，
其他行均为空。服务校验因子返回值的长度、索引、类型、状态枚举和
数值/状态一致性；实现错误应明确失败，不静默丢行、改序或填充结果。

未知因子名、无效输入或破损追溯使整个请求失败并给中文原因；历史不足、
正常缺失以及数值范围异常是逐行不可用状态，不是系统崩溃。全部因子值
不可用时仍返回完整表，并提示没有可用值，不声称已有有效研究结论。

## 7. 价格口径与时间信息边界

沿用研究集合已经统一的 `none/qfq/hfq` 标签和声明依据，不在本步计算
复权或转换口径。未复权也可计算描述性价格动量，但明确提醒其变化可能
受分红、拆并份额等影响，不能当作总回报。同一复权标签也不能证明数据
商采用同一方法；用户声明不等于来源认证。

因子在 t 日仅使用 t 及此前的价格，不读取后续数值，也不把结果提前放
到 t-1 日。不额外将结果整体滞后一日：本步记录计算可用时点，未来策略
决定执行时点。包含 t 日收盘价的结果不能用于声称 t 日收盘前已知信号。

“未使用未来行”不等于“输入在历史当时可得”：后补/修订行情及复权资料
可能属于事后数据。本步输出是固定数据版本上的回顾性价格动量，不提供
无前视偏差的实盘证明，更不提供投资建议或交易指令。

## 8. 验收标准

全部使用临时合成数据，不联网、不读取私人行情或凭证。

1. 定义和注册：默认表只有 momentum_20；合法查找成功，重复、无效
   类型、抽象类、空名、定义不一致和未知名称有明确错误。
2. 手算：21 条完整记录首 20 条为 warmup，第 21 条与 100→110 的 0.10
   一致；另测常价为 0、下跌为负，并核对后续滑动窗口。
3. 时间轴：包含周末/节假日间隔的合成日期验证按位置而非自然日计数；
   在相同研究范围下，显式日历的全体缺失日改变窗口，来源信息随之保留。
4. 缺失：分别覆盖窗口锚点、中间、当前缺失及窗口移出后的恢复；不足
   21 条时全空；全缺失资产保留；零成交量的有效价格仍计算。
5. 数值：非法价格在输入校验阶段拒绝；有限正价的极端比值不输出无穷
   或虚假的 -100%，而是 numeric_range。
6. 多 ETF：不同价格路径独立计算，不串用相邻资产；结果键、顺序、
   行数和无效行与输入完整网格一致；有效预览使用重复或非连续行标签
   时仍可计算，调用方索引不变。
7. 时间隔离：只改后续有效行情，再构建有效输入，较早日期的数值/状态
   不变；允许整个研究输入指纹改变，不错误要求它保持不变。
8. 追溯与不可破坏：修改预览价格、来源、日期轴或已有指纹后运行拒绝；
   正常运行不修改调用方数据，不访问 sources 路径；返回值修改不影响输入。
9. 接口兼容：compute 与 evaluate.values 一致；保留 Series 调用形式；
   非连续但唯一的输入索引可正确保留；因子输出契约损坏明确报错。
10. 端到端：真实合成导入 → 日期对齐 → 保存 → 移走原始目录 → 重读
    → 因子计算。核对手算值、状态与公式/研究输入身份，不 mock 核心计算。
11. 完整回归：运行项目全套测试及依赖一致性检查，报告实际通过/跳过
    数量；第一阶段回测不新增因子依赖。本步无新页面，不宣称完成页面验收。
