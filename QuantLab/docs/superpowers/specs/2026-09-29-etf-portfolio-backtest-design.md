# 多 ETF 单因子等权组合回测：首版设计

日期：2026-09-29。状态：用户已确认本书面设计；进入实施计划编写，尚未开始实施。

本文区分已经确认的业务规则与为实现这些规则提出的技术细节。文档存在
不代表功能已完成，也不代表第二阶段已经验收。审阅通过后才编写实施计划。

## 1. 目标、范围与已有确认

QuantLab 面向学习量化研究的个人用户，本地运行，以 Python 为主，不连接
券商、不自动交易。沿用当前项目目录和分支，保护已有未提交工作。逐步
开发并解释各模块作用，不一次实现整个第二阶段。

已有多 ETF 固定版本研究集合、完整日期轴、严格窗口因子、同日排名及
前 N 只等权配置预览。本次把目标配置推进到可以核对现金、持仓、成交和
每日资产的模拟过程。成功标准不是收益高，而是结果可解释、可手算验证、
不提前使用信号、费用与余额能够对账，且不改变第一阶段单 ETF 功能。

用户已确认：

- 单因子排序，选前 N 只，目标等权；只做多，不融资。
- 默认每 20 期调仓，可修改间隔；期数按研究日期轴位置，不按自然日或月份。
- t 日收盘后生成配置，下一研究日期开盘模拟执行；先卖后买。
- 模拟现金、整手持仓、手续费与滑点，复用既有指标定义。
- 有效因子不足 N 只：跳过本次调仓，保留原持仓和现金；未建仓则继续现金。
- 调仓所需开盘价缺失：停止回测，指出日期和 ETF，不假定成交。
- 持仓 ETF 收盘价缺失：停止回测，不补旧价格、不输出完整期间绩效。

以下章节将上述约定落成首版技术方案；时间表锚点、预算方法、结果接口
和交付边界已随本次书面设计获得确认。

## 2. 路线选择与本小步交付

两条实现路线：

1. **独立现金/持仓引擎（本设计采用）**：逐日记账，能够核对整手、成本、
   余款与未成交原因。比加权收益曲线多一些实现工作，但符合已有确认。
2. 直接用目标权重乘以收益率：适合快速原型，但不能准确表达整手、最低
   佣金和剩余现金，不作为本项目首版组合回测。

本小步交付 Python 核心、合成数据测试、规则与调用说明；核心验收后再以
独立小步接入 Streamlit。此处不提前修改因子研究页面或旧回测页面。

本小步不包含：组合基准比较、胜率/盈亏比与 FIFO 匹配、持久化回测档案、
结果下载、新因子、多因子、月末调仓、优化权重、参数扫描、融资做空、
动态历史资产池、停牌恢复成交、涨跌停和盘口、容量/成交量参与率、公司
行动及现金分红。没有基准时不声称产生超额收益；这些内容仍留在后续路线图。

不增加依赖，不联网取行情，不修改研究集合文件格式或原始数据。

## 4. 配置与调仓时间表

组合配置包含 `top_n`、`rebalance_interval`（默认 20）、`ascending`
（默认按因子方向）以及既有 `BacktestConfig`。N 必须显式提供，不由引擎
暗中选择；N 为 1 至研究集合资产数量的整数。间隔和每手份额为正整数，
布尔值不能充当整数，排序方向只接受布尔值或默认值。所有金额与费率必须
有限，初始资金大于零，费用和滑点非负，滑点小于 1。绩效参数同样检查
有限性、每年期数为正整数及无风险年利率大于 -1。新边界额外校验这些条件，
不放宽或修改旧配置类行为。

沿用研究假设默认值：初始现金 100,000；每手 100 份；佣金率 0.0003；
最低佣金 0；卖出税率 0；滑点率 0.0001。它们不是券商收费承诺，也不是
投资建议。首版全体 ETF 使用同一手数和费用配置。

令日期轴为 `D[0] ... D[M-1]`，所选因子的回看期数为 L，调仓间隔为 K：

- `D[0]` 起为空仓和全部现金，保留整个热身阶段的每日资产记录。
- 计划信号位置固定为 `L, L+K, L+2K, ...`，只保留区间内位置。
- 即使 `D[L]` 因缺失而不足 N，也不重新寻找锚点；下一次仍在 `L+K`。
- 每个计划日在收盘后仅看该日因子。足 N 时生成配置，执行日为 `D[i+1]`。
- 足 N 但位于最后日期时，记录 `EXPIRED`，不成交；不足 N 时优先记录
  `SKIPPED_INSUFFICIENT_FACTORS`，不声称产生了可执行配置。
- 非计划日不会因排名变化而交易；间隔为 1 时也先执行前日配置，再产生
  当日收盘后的新配置，不在同日重复执行。
- 历史长度不足 L+1 时没有计划信号，仍可得到全现金路径及明确警告。

例如动量 20、间隔 20：第 21 个轴日期收盘首次选取，第 22 个轴日期开盘
首次执行，之后信号在第 41、61 个轴日期收盘产生。缺失日期不从轴上删除。

评价区间就是当前研究集合全部日期，包含热身及空仓等待阶段；首版不另设
独立回测起点，也不悄悄从第一次成交重新计算收益或年化。

## 5. 筛选、目标与执行预算

### 5.1 收盘后的目标

仅 `is_valid=True` 的有限原始因子值参与排序。动量默认降序，历史波动率
默认升序，允许显式反向；零和负因子值仍参与，不另加择时过滤。相同原始
值按 ETF 代码升序确定席位；恰好选 N 个，不用“名次 <= N”扩张数量。
并列跨越 N 的边界时记录警告，说明代码规则不表示投资优劣。

不足 N 时只记录跳过，不生成空目标组合、不清仓、不减少 N、不使用旧因子。
足 N 时每只目标权重为未舍入的 `1/N`；未入选资产的目标份额为零。

### 5.2 下一期开盘后的份额目标

开盘只为前日已选好的代码计算执行数量，不利用开盘价格重新排名。
需要有效开盘价的集合是“开盘前仍持有的 ETF 与目标 ETF 的并集”。
先一次性检查该集合，缺价则整个回测失败，不跳过订单或找后一天价格。

用未加滑点的开盘价计算交易前资产：

`E_open = cash + sum(held_quantity[i] * open[i])`

对入选 ETF，目标份额为：

`q_target[i] = floor((E_open / N) / (open[i] * lot_size)) * lot_size`

先卖出当前份额高于目标的差额；未入选者全部卖出。卖出数量不超过原持仓，
不做“全部卖光再买回”的无必要换手。已入选且份额相同者不下单、不收费。
目标按交易前资产计算一次，不反复按扣费后资产迭代追求精确等权。

### 5.3 买入预算与剩余现金

卖出完成后，记录可用现金 C。各待买资产的最大增量为正的目标差额 `d_i`，
已包含整手取整。买入滑点价记作 `p_i`；完整需求成本：

`need_i = d_i * p_i + max(d_i * p_i * commission_rate, minimum_commission)`

- 若完整需求成本之和不超过 C，买足全部增量。
- 若超过 C，先按完整需求成本占比分配独立含费预算：
  `budget_i = C * need_i / sum(need)`；再在各自预算中寻找不超过 `d_i`
  且能够支付佣金的最大整手数量。
- 所有预算在买入前同时确定，不能让代码排前的 ETF 先耗尽现金。
- 取整后剩余现金留存，不二次分配、不借款、不买不足一手的份额。
- 计划买入但实际数量为零时保留拒绝原因；只买到部分数量时同时记录
  申请量、成交量和未满足数量，不把它描述成完全实现目标。

先卖后买；每一侧按代码升序记录，保证复现。排序只是记录顺序，不能改变
预先分配的买入预算。极小浮点误差使用统一容差检查和零值归整，不得让
容差成为可用融资或消掉真实费用。计算发生溢出/非有限数值时明确失败。

## 6. 费用、估值与严格失败

买入价 = open × (1 + 滑点率)；卖出价 = open × (1 - 滑点率)。
每只 ETF 每次实际订单分别收佣金 `max(成交额 × 佣金率, 最低佣金)`；
卖出另收成交额 × 卖出税率。未实际成交的订单不收费。
滑点已体现在成交价格，不再从现金重复扣除；另记录滑点金额用于解释成本。
累计佣金及税费与累计滑点金额分列，避免改变旧代码的成本字段含义。

每天完成当日开盘交易后，用收盘价估值：

`equity = cash + sum(end_of_day_quantity[i] * close[i])`

估值只检查正持仓资产的当日有效收盘价；未持有、未参与调仓的资产缺失，
不单独导致回测停止。已全部卖出的资产不再参与后续收盘估值。买入后若
无法获得有效收盘价，不能显示一条未经完整估值的成功交易日。

以上不放宽研究输入校验：当前研究网格的观测行要求 OHLCV 完整有效，
无观测行则五个字段全部为空。“有开盘价但收盘价为空”的部分损坏行会
在输入校验阶段被拒绝，不能因当天计划卖出而获准通过。

严格失败规则：

- 研究输入身份/网格损坏、非法配置、所需开盘价缺失、正持仓收盘价缺失、
  现金/份额为负或数值不可可靠表示，均抛出带原因的组合错误，不返回成功结果。
- 在副本中完成当日模拟和不变量检查后才接受当天状态；失败不修改输入，
  不保存部分成果，不提供截断曲线冒充完整期间结果。
- 交易费用极端到使一笔卖出净收入为负时，报配置/资金错误，不静默拒绝
  必需的卖出而继续展示成功调仓。
- `has_observation` 不等于可交易。若拟实际成交资产的当日记录为零成交量，
  首版拒绝整个回测并提示成交假设不受数据支持；不把它作为选股过滤，
  不换选第 N+1 只，也不把当天的最终成交量用于开盘时策略决策。

当日成交量检查是回顾性模拟的输入适用性限制，不声称开盘时已经知道
全天成交量。即使成交量大于零，也不证明开盘可按该价成交；首版没有
交易状态、盘口、涨跌停或容量模型。

闲置现金利息为零；期末不强制平仓；分红、拆并份额等不单独入账。

## 7. 结果、绩效与可追溯性

`PortfolioBacktestResult` 至少包含以下独立表及运行信息：

| 结果 | 必需内容 |
| --- | --- |
| `decisions` | 计划信号日、预期执行日、可用数量、N、状态/原因、边界并列标记 |
| `targets` | 决策身份、信号日期、入选代码、原始因子值、目标权重 |
| `orders` | 决策/订单身份、代码、买卖方向、信号/执行日期、申请量、成交量、状态/原因 |
| `trades` | 订单/成交身份、代码、成交份额、原开盘价、含滑点价、成交额、佣金、税、滑点金额、成交后现金和该资产份额 |
| `positions` | 每个轴日期、全部研究代码、期末份额、市值、实际权重；空仓市值为 0，不因缺失价格变成虚假零价 |
| `equity_curve` | 每个轴日期、现金、总持仓市值、总资产、净值、累计收益、累计佣金税费和滑点金额 |
| `metadata` | 配置、因子定义、输入身份、日期轴、价格口径、限制、代码/环境与运行身份 |

订单状态为 `FILLED`、`PARTIALLY_FILLED`、`REJECTED`；无数量差额不生成
订单。未到执行日期的末期信号在决策中记 `EXPIRED`，不伪造逐 ETF 成交。
决策状态区分 `EXECUTED`、`SKIPPED_INSUFFICIENT_FACTORS`、`EXPIRED`；
`EXECUTED` 只表示执行流程完成，须结合订单/成交表判断实际买入情况。

资金曲线第一条为未交易初始资金，净值为 1。总收益和净值以初始资金为基准，
不丢失首次建仓成本。每一期的资产变化都能从价格变化和当期成本核对。
空仓行即使没有任何价格观测，也可由现金准确估值；因此不能把缺价 ETF
当成零收益，也不能要求全资产在所有日期都有价格才允许运行。

绩效复用 `analytics/returns.py`、`analytics/risk.py` 的公式和校验：
简单期收益、复合年化、样本波动率、最大回撤、夏普比率；年化默认每年
252 期、无风险利率 0，显式记录参数。完整热身与空仓区间纳入计算。

新组合分析适配层逐项调用既有函数，不修改第一阶段 `analyze_performance`
遇未定义指标时报错的契约。只有一条资产观测时，累计/年化收益、波动率和
夏普标记不可计算；至少两条可算累计/年化，至少三个资产观测才可算样本波动。
夏普依照既有标准差阈值判断，常数资产曲线的夏普为未定义，不是零或无穷。
可定义的净值和回撤仍正常返回。未定义指标采用 `None + 原因`，不捕获并
隐藏其他程序错误。有效全现金路径与数据错误导致的失败必须区分。

运行身份记录：独立运行 ID/时间、组合规则版本、因子完整定义及版本、
N/K/方向/时间表锚点、资本和费用参数、研究预览与对齐指纹、因子结果内容
指纹、全部日期轴声明、白名单来源版本信息、价格口径、源码内容指纹、
Python 和核心数值库版本。结果保留实际使用的行情与因子独立内存快照，
不附加凭证、机器数据路径或个人交易内容。

复用现有 `backtest/provenance.py` 的源码加载基线、运行前一致性校验和
数据指纹辅助能力，不另建代码认证系统，也不强套单 ETF 存档协议；新增
组合身份以独立版本命名。加载后改了源码须拒绝运行并要求重启，不能把
新磁盘哈希冒充仍在内存中的执行版本；此检查也不等于独立代码认证。
确定性测试比较业务输出，排除每次变化的运行 ID/时间。
本小步不写入回测档案目录，不承诺自动恢复历史执行环境。

## 8. 数据与研究结论边界

- 日期并集可能漏掉所有 ETF 同时无记录的日期；用户日历也未获官方认证。
  下一研究日期不必然是下一官方交易日，252 期年化依赖日线等间隔假设。
- 保留 `none/qfq/hfq` 口径，不混用或转换；未复权未处理公司行动，不是
  含分红总回报；复权价并非真实历史成交价。复权数据下的份额与整手只是
  该价格坐标中的模型单位，不能声称等同历史真实可买份额。
- 同一标签不保证数据商算法相同。固定版本可能含事后修订/复权信息，
  没有未来行参与决策不等于输入当时可得。
- 当前静态 ETF 集合不是历史逐日可投资池，仍可能有幸存者偏差。
- 等权是目标而非每日实际权重保证；费用、取整、价格变动、预算不足和
  跳过调仓都可能产生偏离。记录真实模型持仓，不强行把权重归一化到满仓。

这些限制必须随结果保留。首版不作可实盘复制、无偏估计或策略有效性承诺。

## 9. 验收标准

使用独立临时合成数据；不读取私人行情、凭证，不联网取行情。

1. 配置：非法 N/K、布尔整数、非有限金额/费率、非法滑点/手数明确失败。
2. 时间表：20/60/120 回看与不同 K 的锚点；周末/日期缺口按位置计数；
   不足 N 跳过后不重置时间表；最后日足 N 过期；短历史全现金。
3. 因子：五个内置因子、默认及反向排序、有效零/负值、精确并列与显示
   舍入假并列、N 边界、少于 N、原始数据与 UI 预览选择一致。
4. 防提前使用：前日信号只能次日开盘成交；只改变后续有效价格和因子输入，
   较早决策/成交/资产保持不变。允许整个输入指纹随新快照改变。
5. 手算：无费用时两资产首次等权、保留/减仓/换入/换出、同日先卖后买、
   不必要交易为零、末期仍持仓，与人工账本一致。
6. 预算：预留滑点和佣金、最低佣金、卖出税、资金不足一手、比例缩减、
   不再分配余款、调换代码输入顺序不改变预算和业务结果。
7. 记账不变量：每笔现金变动准确；各代码份额非负且为整手；总资产等于
   现金加各持仓市值；实际权重与现金权重合计为 1（容差内）；不重复扣滑点。
8. 缺失：所需开盘缺失失败；持仓收盘缺失失败；非持仓无关缺失不误报；
   已全部卖出的资产在后续日期缺失不误报；跳过调仓仍须检查原持仓收盘；
   仅部分 OHLCV 为空的损坏观测行仍被输入校验拒绝。
9. 失败：拟成交资产零成交量、非有限运算、极端费用等按规则报错；失败
   不返回部分成功结果、不留下文件、不改变输入。
10. 绩效：首次成本计入、完整热身区间、期末不强平；普通路径与原指标
    一致；全现金夏普未定义、短样本各项原因清晰；失败路径无完整绩效。
11. 追溯：修改输入内容/身份拒绝；源文件移走后已载入研究快照仍可回测；
    返回值不影响调用方；实际因子定义、参数和源码身份可核对。
12. 合成端到端：导入 → 对齐 → 保存/重读 → 因子 → 调仓 → 持仓/资产
    → 绩效，核心步骤不以 mock 替代；再执行全项目回归与依赖检查。

本轮是文档设计，不执行也不宣称以上测试已通过。将来实施时先编写能观察
失败的测试再实现，按小步解释代码作用。核心验收不冒充 UI、真实行情、
实盘可成交性或整个第二阶段验收。
